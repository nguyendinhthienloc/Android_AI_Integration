\section{Introduction}

InkClear is an Android application for photographed handwritten documents. The release described in this report combines two pretrained neural pipelines: a document-binarization network cleans shadows and uneven paper, while PP-OCRv5 Mobile detects and recognizes text. Both pipelines are bundled in the application and execute locally. The user starts OCR explicitly, reviews editable text on a dedicated screen, and can copy it or save a UTF-8 text file.

No model training is required on the user's computer. The original deterministic enhancer remains available automatically when neural cleanup cannot start.

\section{Product decisions}

The agreed scope is English-first OCR, offline-only inference, one page at a time, explicit recognition after a button tap, a dedicated editable result screen, and plain-text export. Searchable PDF and model training are outside this release. The minimum Android version was allowed to change to satisfy the official mobile OCR SDK.

\section{User workflow}

\begin{enumerate}[leftmargin=*]
  \item The user selects an image or opens the optional one-page document scanner.
  \item InkClear decodes and bounds the image to a maximum dimension of 1800 pixels.
  \item Neural Clean runs in the background and displays its result. If loading or inference fails, the classical enhancer is used.
  \item The user compares Original and Neural Clean, selects Natural, Grayscale, or Black and White, and adjusts strength.
  \item The user taps Recognize text. PP-OCRv5 detects and recognizes lines locally.
  \item A dedicated result activity shows the source preview, runtime metadata, confidence, and editable text.
  \item The user copies text, saves a UTF-8 \texttt{.txt} file, or requests recognition again.
\end{enumerate}

JPEG and image-only PDF export remain available for the cleaned page.

\section{Neural Clean pipeline}

\subsection{Model selection}

A large SBB cleanup SavedModel was evaluated first. Its float16 conversion remained approximately 75 MB and depended on \texttt{tf.ExtractImagePatches}, requiring TensorFlow Flex. That candidate was rejected for mobile deployment.

The selected model is the Apache-2.0 pretrained network from \href{https://github.com/sliedes/binarize}{sliedes/binarize}, revision \texttt{f40863ed4f2869add585f8a133af29c37844ffee}. It has 6,501,345 parameters and was converted from TensorFlow SavedModel to a dynamically weight-quantized 6,906,912-byte LiteRT file.

\subsection{Input, tiling, and rendering}

The model accepts RGB float input with shape \(1 \times 224 \times 224 \times 3\), using pixel values from 0 to 255, and produces one paper/ink logit per pixel. InkClear bounds the inference canvas to 896 pixels, divides it into non-overlapping 224-pixel tiles, applies a stable sigmoid and strength-controlled contrast, and upscales the mask to the source resolution.

Natural mode restores limited source chroma; Grayscale emits enhanced luminance; Black and White thresholds the neural mask. This one-pass mobile adaptation is faster than the upstream desktop method, which uses overlaps and rotations, but may lose detail in very small writing.

\subsection{Conversion validation}

The original TensorFlow and converted LiteRT models were compared on the handwritten DIBCO 2009 sample \texttt{dibco09\_hand\_H01.png}. The mean absolute logit difference was 0.10663 and the maximum was 0.67612. These values validate conversion similarity, not end-user cleanup quality. A separate Android instrumented test runs the packaged model end to end.

\section{Offline OCR pipeline}

The project vendors the official PaddleOCR Android SDK at revision:
\begin{center}
\texttt{2661c7c0ef5c613e8f93c6e93b2e052399f0f854}
\end{center}
It bundles:

\begin{itemize}[leftmargin=*]
  \item PP-OCRv5 Mobile detection ONNX model, 4,826,518 bytes;
  \item PP-OCRv5 Mobile recognition ONNX model, 16,534,782 bytes;
  \item the recognition character configuration;
  \item ONNX Runtime Android and official OpenCV Android.
\end{itemize}

\texttt{OfflineOcrEngine} lazily creates the native engine only after the button tap. Detection finds line quadrilaterals; boxes are sorted in reading order; OpenCV performs perspective crops; recognition decodes each crop; and \texttt{OcrTextFormatter} normalizes whitespace while preserving line and paragraph structure.

Recognition owns a cancellable job. A request generation counter prevents stale text from opening after the image or enhancement settings have changed. The OCR engine releases ONNX sessions during activity destruction.

\section{Privacy and data handling}

All models are application assets. The source manifest explicitly removes \path{android.permission.INTERNET} and \texttt{ACCESS\_NETWORK\_STATE}, including declarations introduced by transitive libraries. An instrumented test verifies the merged installed package has no Internet permission.

The app does not log image pixels or recognized text, does not retain OCR history, and does not request broad storage access. JPEG, PDF, and TXT output use Android's system document picker. The optional Play-services scanner can be unavailable; the standard image picker is the fallback.

\section{Interface design}

The visual system uses a navy/blue palette, light paper surfaces, Neural Clean and Offline status chips, and a new adaptive launcher icon showing a sheet, handwriting, cleaned lines, and a sparkle. The OCR result screen is scroll-safe under compact displays and large accessibility scaling. It provides editable/selectable text, metadata, character count, Copy, TXT export, retry, and empty-result guidance.

\section{Testing}

\subsection{Local tests}

Local tests cover horizontal whitespace collapse, paragraph preservation, leading/trailing blank removal, empty input, Unicode preservation, and numerical stability of the neural sigmoid.

\subsection{Instrumented tests}

Five instrumented tests pass on the \texttt{Resizable\_Experimental} Android Virtual Device:

\begin{enumerate}[leftmargin=*]
  \item bundled neural and OCR model assets are present and Internet permission is absent;
  \item Recognize text is disabled before an image is ready;
  \item result text is displayed, editable, scroll-safe, and updates its character count;
  \item the real bundled PP-OCRv5 detector and recognizer execute end to end offline;
  \item the real bundled LiteRT Neural Clean model executes end to end offline.
\end{enumerate}

The OCR runtime fixture is PaddleOCR's official \texttt{android\_ocr\_benchmark\_reference.png}. Synthetic English and Unicode strings exercise the formatter and UI.

\subsection{Scope of evaluation data}

The current fixtures prove conversion fidelity, packaging, privacy, lifecycle behavior, UI editing, and native inference. They do not provide a statistically meaningful handwriting-accuracy estimate. A future evaluation should use the IAM Handwriting Database for English line/word samples plus consented phone photographs covering pen, pencil, ruled paper, shadows, glare, cursive, and multiple writers. Character error rate and word error rate should be reported with writer-disjoint splits.

\section{Build and verification}

A valid JDK 17 or 21 and Android SDK Platform 37 are required. The official PaddleOCR Android SDK raises the minimum runtime to API 26. Typical verification commands are:

\begin{lstlisting}[language={},caption={Build and test commands}]
.\gradlew.bat test
.\gradlew.bat lint
.\gradlew.bat assembleDebug
.\gradlew.bat :app:assembleDebugAndroidTest
.\gradlew.bat :app:connectedDebugAndroidTest
\end{lstlisting}

The debug APK is written to \texttt{app/build/outputs/apk/debug/app-debug.apk}. The first developer build needs Internet access to download Maven dependencies, but the installed application does not.

\section{Limitations}

\begin{itemize}[leftmargin=*]
  \item Dense cursive, touching lines, blur, glare, perspective, abbreviations, equations, and unusual symbols can reduce OCR accuracy.
  \item English is the release target; incidental recognition of other scripts is not guaranteed.
  \item Neural cleanup uses an 896-pixel inference bound for responsiveness, which can weaken very small strokes.
  \item Confidence is an average model score and is not a guarantee of correctness.
  \item The app processes one page at a time and does not create searchable PDFs.
  \item Bundled models and native runtimes substantially increase APK size.
  \item Physical-device latency and memory benchmarking remains necessary before production release.
\end{itemize}

\section{AI usage statement}

AI tools supported model research, conversion experiments, Android integration, UI concepts, test design, documentation, and troubleshooting. Every delivered path was checked through source inspection and automated builds. The converted model was numerically compared with its original TensorFlow source, and both neural pipelines were executed in Android instrumented tests. \section{Conclusion}

InkClear now contains meaningful pretrained neural functionality rather than a simulated AI label. It cleans documents with LiteRT, recognizes handwriting with PP-OCRv5, remains usable through a classical fallback, exposes an editable text workflow, and enforces an offline permission boundary. The next engineering milestone is a writer-disjoint English accuracy and performance benchmark on physical devices.
